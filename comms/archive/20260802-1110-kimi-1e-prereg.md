# 1e pre-registration (pin BEFORE run, C protocol) — partial-ID overlap + warm-start rebind

**1e-a — partial-ID overlap probe (zero training, read-only on frozen
loan students).** Build loan_e1s/e2s variants with 50% of entities
renamed (fresh ids + glosses; the OTHER half keeps trained codes),
gate the 2 frozen loan students. Decision rule: if both seeds resolve
at 50% (ranks ≤ ~8) ⇒ transfer is a SLOPE in overlap fraction (the ID
wall is graded; partial-code migrations are survivable — the
productization answer for evolving rulebooks). If 50% fails like
100%-fresh (ranks 14–16 / unresolved) ⇒ CLIFF: any fresh code
fraction collapses the binding, and rulebook migrations require
retraining (the 304s drill becomes the mandated path). Intermediate
(1/2 seeds, degraded ranks) = slope with curvature; recorded, both
levers priced.

**1e-b — warm-start rebind (ONE training run, registered).** Fine-tune
frozen loan-gpt2-s12345/best on train_loan_rc2.jsonl (the v2 rate
card), SAME hyperparams as the from-base rc2 run (5 epochs, batch 8,
lr default), from the v1 checkpoint — with the forgetting guard: full
re-gate (LN-E1S + LN-E2S + twins). Decision rule: warm-start passes
both gates AND twins at < 60% of the from-base wall time ⇒ the
revalidation-cost claim STRENGTHENS (update path, not retrain path).
Twin flips > 0 OR E2S resolution lost where from-base kept it ⇒ warm
revalidation has a hidden forgetting price — the from-base 304s drill
stays the mandated path and the warm path is priced separately.
Executed on the instance, gpt2 only (the business case's scale);
qwen05 is out of scope for the productization numbers (D showed its
brittleness; not the deployment student).

Both report as `result` mail with refs. C synthesis ACK from your
side awaited in parallel — no dependency.
